# TCP 协议

TCP（Transmission Control Protocol，传输控制协议）是一种**面向连接的**、**可靠的**、基于字节流的传输层协议。

## 三次握手

TCP 通过三次握手建立连接：

1. 客户端发送 `SYN` 报文，进入 SYN_SENT 状态；
2. 服务器回复 `SYN+ACK` 报文，进入 SYN_RCVD 状态；
3. 客户端发送 `ACK` 报文，双方进入 ESTABLISHED 状态。

为什么需要三次握手而不是两次？三次握手可以防止**已失效的连接请求报文**突然又传送到服务器，导致服务器错误地建立连接、浪费资源。

## 四次挥手

TCP 断开连接需要四次挥手。因为 TCP 是全双工的，每个方向都必须单独关闭。主动关闭方在发送最后一个 ACK 后进入 **TIME_WAIT** 状态，等待 2MSL 后才真正关闭。

## 可靠传输

TCP 的可靠性由以下机制保证：

- **序列号与确认应答**：每个字节都有序列号，接收方通过 ACK 确认；
- **超时重传**：在超时时间内没有收到确认就重传；
- **流量控制**：通过接收方通告的**滑动窗口**控制发送速率，防止接收方缓冲区溢出；
- **拥塞控制**：通过慢启动、拥塞避免、快重传和快恢复，防止网络拥塞。

> 流量控制关注的是接收方的处理能力，拥塞控制关注的是整个网络的负载。

## TCP 与 UDP 的比较

| 特性 | TCP | UDP |
| --- | --- | --- |
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠 | 不可靠 |
| 首部开销 | 20 字节起 | 8 字节 |
| 适用场景 | 文件传输、网页 | 视频通话、DNS |

更多内容参见 [UDP 协议](传输层/UDP协议.md)。
