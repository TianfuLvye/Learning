# Markdown 驱动的 AI 知识学习系统

把 Markdown 文件放进 `learn/` 目录，即可在本地获得一个“阅读 → 练习 → 复习反馈”的学习环境：

- **阅读**：书籍式双页阅读（窄屏自动切换为单页），按块分页，不拆分标题、段落、表格、代码块等结构；
- **练习**：DeepSeek 依据当前文章生成**选择题**（单选/多选）、**原文挖空**（直接在原文中填空）和**问答题**；
- **复习反馈**：左侧对照原文，右侧查看选择题解析、挖空答案、问答点评与原文依据（可调宽、可折叠）；
- **学习进度**：未开始 / 学习中 / 已完成，目录递归统计，保存在 `learn/.progress.json`。

技术栈：React + TypeScript + Vite（前端），Node.js + Express（后端），unified / remark / rehype（Markdown AST），Zod（AI 输出校验）。

---

## 1. 环境准备

- Node.js **20 或更高版本**（开发与测试使用 Node 22）
- npm 10+
- 一个 DeepSeek API Key（可选；没有也可以阅读与管理进度）

## 2. 安装依赖

```bash
npm install
```

## 3. 配置 DeepSeek API Key

```bash
cp .env.example .env
```

编辑 `.env`：

```ini
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_TIMEOUT_MS=120000     # 单次请求超时
DEEPSEEK_MAX_RETRIES=2         # 失败后的最大重试次数
DEEPSEEK_MAX_TOKENS=8000
DEEPSEEK_TEMPERATURE=0.3
```

- API Key 只在后端读取，所有 AI 请求都由后端发起，浏览器中看不到 Key。
- 修改 `.env` 后需要**重启服务**。
- 未配置 Key 时：阅读、目录导航、手动标记进度正常可用；AI 功能会显示配置提示。



## 4. 放置学习资料

把 Markdown 文件（`.md` / `.markdown`）放进 `learn/`，支持任意层级子目录：

```
learn/
├── 入门指南.md
├── 操作系统/
│   ├── 进程管理.md
│   ├── 内存管理.md
│   └── images/process-states.svg
└── 计算机网络/
    ├── TCP协议.md
    └── 传输层/UDP协议.md
```

- 图片使用相对于当前文档的路径即可，例如 `![状态图](images/process-states.svg)`；也支持外部图片 URL 和带链接的图片。
- 文档之间的相对链接（如 `[TCP](../计算机网络/TCP协议.md)`）会在应用内跳转。
- 新增、删除、移动文件后目录树会自动刷新（文件监听 + SSE 推送）。移动/重命名但内容未变的文件会自动迁移学习进度。
- 以 `.` 开头的文件和目录不会显示，也无法通过接口访问。



## 5. 启动

**开发模式**（前端热更新 + 后端自动重启）：

```bash
npm run dev
```

浏览器打开 [http://localhost:5173](http://localhost:5173)。后端运行在 3001 端口，Vite 会把 `/api` 代理过去。

**生产模式**（后端托管构建好的前端，只需一个端口）：

```bash
npm run build
npm start
```

浏览器打开 [http://localhost:3001](http://localhost:3001)。

## 6. 使用说明


| 操作          | 说明                               |
| ----------- | -------------------------------- |
| 打开文档        | 左侧目录点击文件；首次打开自动标记为“学习中”          |
| 翻页          | 底部按钮或键盘 ← / →；🔗 按钮切换左右页同步滚动     |
| 阅读设置        | 顶栏 **T** 按钮：字号、行高、阅读宽度（自动保存到浏览器） |
| 开始练习        | 切换到“练习”，选择题型后点击“开始生成”            |
| 重新作答 / 重新生成 | 练习顶部按钮；重新生成会忽略缓存再次调用 DeepSeek    |
| 复习反馈        | 提交后点击“进入复习与反馈”或顶栏“复习反馈”          |
| 标记完成 / 重新学习 | 顶栏右侧按钮；成绩与完成状态分开保存，重新答题不会清除完成标记  |


切换模式不会丢失状态：阅读位置、已选选项、已填空格、问答草稿都会保存在浏览器本地，刷新后仍在。

## 7. 修改提示词

提示词全部位于 `prompts/`，每次 AI 请求都会**重新读取文件**，修改后无需重启、无需改代码：


| 文件                       | 用途      |
| ------------------------ | ------- |
| `prompts/mcq.md`         | 选择题生成   |
| `prompts/cloze.md`       | 原文挖空生成  |
| `prompts/qa_generate.md` | 问答题生成   |
| `prompts/qa_evaluate.md` | 问答题答案点评 |


文件格式：

```markdown
<!-- system -->
系统提示词……

<!-- user -->
用户提示词模板，使用 {{article}}、{{count}} 等变量……
```

可用变量写在每个文件顶部的注释中。注意事项：

- 请保留 JSON 输出格式说明——DeepSeek 的 JSON 模式要求提示词中出现 “json” 字样，且服务端会按固定 Schema 校验；
- 提示词内容的哈希会作为缓存键的一部分，修改提示词后，下一次生成会自动使用新提示词（旧缓存不再命中）。

挖空题的同义答案可以在 `config/synonyms.json` 中配置（同义词组数组），例如 `["TCP", "传输控制协议"]`。

## 8. 工作原理（要点）



### 原文挖空

1. 前后端共用同一套解析器（`shared/markdown.ts`：remark-parse + remark-gfm），把文章解析为 AST；
2. 每个可挖空的文本节点用它在源文中的起始偏移量作为稳定 ID（如 `t128`）；代码、行内代码、链接、图片、HTML、标题内的文本不参与挖空；
3. 把“节点 ID + 节点文本 + 所在段落上下文”发给 DeepSeek，模型返回 `nodeId`、`answer`、`occurrence`（第几次出现）和解析；
4. 服务端校验：节点存在、答案在节点文本中**逐字出现**、出现序号能唯一定位、与其他挖空不重叠。无法可靠定位的条目直接跳过，有效条目过少则自动重新生成；
5. 前端在 **AST 层**把目标区间替换为挖空节点，再渲染为输入框——加粗、链接、表格等原有结构保持不变，从不修改 Markdown 字符串；
6. 判分在服务端完成：NFKC 标准化（全半角）、忽略大小写/空白/标点，并接受模型给出的等价写法和 `config/synonyms.json` 中的同义词。



### 选择题与问答题

- 服务端校验选项 ID 唯一、`correctOptionIds` 与每个选项的 `isCorrect` 一致、单选恰有一个正确答案（自动修正题型标注），不一致的题目丢弃；
- 下发给浏览器的题目**不含答案和解析**，提交后由服务端判分并返回解析；
- 问答题的评分要点与参考答案只保存在服务端，点评时连同原文、学生答案一起发给 DeepSeek；
- 模型给出的“原文依据”会与原文比对，无法在原文中找到的会标注“未能在原文中定位”。



### 可靠性

- 所有 AI 输出都经过 Zod Schema 校验 + 语义校验；
- 处理无效 JSON（含 ```json 代码块包裹）、字段缺失、空响应、输出截断（自动增大 max_tokens 重试）、网络错误、超时、限流、认证失败、余额不足；
- 可重试的错误按指数退避重试 `DEEPSEEK_MAX_RETRIES` 次；认证/参数错误不重试；
- 用户取消或离开页面时，后端会中止上游请求；
- 练习缓存在 `.cache/exercises/`，缓存键 = 题型 + 文档路径 + 文档内容哈希 + 提示词版本 + 模型配置。



### 安全

- 文件访问限制在 `learn/` 内：拒绝 `..`、绝对路径、隐藏文件、指向外部的符号链接；资源接口只返回白名单内的图片等类型，并附带沙箱 CSP；
- Markdown 中的 HTML 经 rehype-sanitize 过滤：移除 `<script>`、事件属性、`javascript:` 等危险协议；
- 进度与成绩文件采用“写临时文件 + fsync + rename”的原子写入，同一文件的读写串行化；文件损坏时自动备份为 `.corrupt-<时间戳>` 而不是覆盖。



### 图片

发送给模型的文章中，图片会被替换为 `[图片：alt 文本（图片内容不可见）]`，提示词也要求模型不要针对图片出题。目前**没有**实现图像理解；如需基于图片出题，需要接入明确支持图像输入的模型并单独实现。

## 9. 数据文件


| 位置                     | 内容                      |
| ---------------------- | ----------------------- |
| `learn/.progress.json` | 学习状态（键为相对 `learn/` 的路径） |
| `learn/.scores.json`   | 练习成绩与历史（与学习状态分开保存）      |
| `.cache/exercises/`    | 已生成的练习（可随时删除，删除后会重新生成）  |

## 10. 测试

```bash
npm test            # 单元 + 接口测试（Vitest，使用本地假 DeepSeek 服务，不消耗额度）
npm run typecheck   # TypeScript 类型检查
npm run build && npm run e2e   # 无头浏览器端到端测试（需要 Chromium，可用 CHROME_PATH 指定）
```

- `tests/markdown.test.ts`：AST 节点标识、挖空跳过规则、重复词定位、中文/特殊字符、AST 替换保留行内格式、答案标准化、路径与协议校验；
- `tests/api.test.ts`：多级目录与递归统计、进度持久化、文件移动/删除、路径穿越与符号链接防护、未配置 Key 的降级；
- `tests/ai.test.ts`：答案不泄露、服务端判分、一致性校验、无效 JSON/截断/空响应/网络错误/限流/超时/认证错误、重试次数、缓存命中与强制重新生成、修改提示词后生效、问答点评；
- `scripts/e2e.ts`：在真实浏览器中验证渲染、图片、相对链接、字号持久化、分页无裁切、选择题与挖空的完整流程、复习反馈、进度持久化、问答点评、390px / 834px 布局无横向溢出。截图保存在 `scripts/screenshots/`。

调试时也可以单独启动模拟服务：`npm run mock:deepseek`，然后在 `.env` 中设置 `DEEPSEEK_BASE_URL=http://127.0.0.1:3010`、`DEEPSEEK_API_KEY=任意值`。

## 12. 已知限制

- 未使用真实 DeepSeek API 进行验证（开发环境无 Key），AI 流程通过遵循 OpenAI 兼容格式的模拟服务测试；真实模型的出题质量取决于提示词，可在 prompts/ 中调整。
- 分页以顶层块为单位：超过一页高度的单个块（很长的表格或代码块）会在该页内部滚动，而不是跨页拆分；块较大时页尾可能留白。
- 很长的文章发送给模型时会截断到约 3 万字符，后续内容不会出题。
- 图片内容不参与出题（见上文“图片”）。
- 作答草稿保存在浏览器本地，换浏览器不会同步；学习进度和成绩保存在服务端文件中。
- 文档内容修改后，旧练习会提示“已过期”，需要手动重新生成。
